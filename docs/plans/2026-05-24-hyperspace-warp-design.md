# Hyperspace Warp Animation — Design

Date: 2026-05-24

## Goal

Animate a first-person "hyperspace travel" cinematic of following a Pathfinder
Drive route: a cockpit-style view where stars streak past with parallax as you
fly a heading from one system toward another. Start with a small **canned demo**
(a few showcase routes) to prove the concept, structured so the same engine can
later power a standalone route picker and a per-jump-page "Fly this route"
button with no rewrite.

## What the data supports

- **Real positions** for all 505 systems (`systems.position_x/y`). The galaxy is
  **2-D** — there is no `z`. This is the one real gap: a first-person starfield
  needs a synthesized depth/height per star.
- **Spectral class** (Morgan–Keenan) for 374/505 suns (`pois.type='sun'.class`),
  e.g. `G2V`, `M2V`, `B2III`, `DA` (white dwarf), `M2Ia` (supergiant), `BH`
  (black hole). Drives color + size/brightness. ~131 lack a class → dim white.
- **Route geometry** is fully derivable: for any heading, each star's along-track
  distance `proj` and signed lateral offset `perp` give exactly when and how
  close it sweeps past. Speed is fixed at 10 GU/tick.

## Architecture

Three separated pieces; the demo and later interactive forms share the core.

1. **`kb/systems/stars.json`** — new build artifact (generated by the Go
   generator alongside `routes.json`): `[{id, name, x, y, class}]` for all 505
   systems, sorted by id, compact. ~30 KB. Only galaxy data the engine needs;
   all visuals derive from `class` at runtime.

2. **`kb/warp.js`** — dependency-free engine (no three.js). Entry point:
   `playWarp(canvas, { origin, dest, stars, opts }) -> { play, pause, replay }`.
   Computes per-star `proj`/`perp` from `origin`+`dest`, fabricates stable depth,
   runs the `<canvas>` loop. Page-agnostic. Risky math factored into pure
   functions: `projection`, `classToColor`, `seededHeight`.

3. **`kb/did_you_know/hyperspace_warp.html`** — canned demo page (hand-authored,
   like other Did You Know pages). Loads `warp.js` + `stars.json`, autoplays the
   showcase routes with captions + Replay. Linked from the Did You Know index.

Data flow: Go generator → `stars.json` (+ existing `routes.json`) → demo page
loads both → `warp.js` renders.

## Visual & projection model

Camera flies along the route: `C = origin + t·dir`, looking down heading `dir`,
`t` advancing at 10 GU/tick (scalable for watchability).

Per star, per frame:
- Fixed per route: `proj = (S−origin)·dir`, `perp = (S−origin)×dir` (signed
  lateral — real left/right placement is preserved).
- `forward = proj − t` (depth ahead). Render only `near < forward < far`; once
  `forward ≤ 0` the star has passed and drops out.
- Fabricated **vertical** `z = seededHeight(id)` (hash the id → stable value in a
  band) so stars fill a volume instead of collapsing onto the travel plane.
  Horizontal stays real (`perp`); only height is synthetic.
- Pinhole projection: `sx = cx + focal·perp/forward`, `sy = cy + focal·z/forward`.
  As `forward → 0` the star sweeps outward fast → the warp streak.
- **Streak** drawn from last frame's point to current; length ∝ angular speed.
  **Brightness/size** ∝ luminosity / distance².

Color/size from `class` (blackbody-ish): O/B blue → A/F white → G yellow →
K orange → M red; luminosity class scales size (V ×1 → III ×2 → Ia ×4).
Specials: `DA` small white-blue, `BH` a dark lensing ring. Missing → dim white.

Dramatic beats: destination star sits dead-ahead (`perp≈0`), swelling into an
arrival flash. For a **blocked** route, the first interrupter (perp ≤ 100) is
flown *into* — the clip ends on its flare, visually explaining the drop-out.

## Demo content

Three showcase routes, each a `<canvas>` + caption with the real numbers:
1. **The squeeze — Inquill → Alrakis** (0.0003° tolerance; Tianyi skims 0.01 GU
   past mid-flight — shows why the tolerance is hair-thin).
2. **The clean long-haul — Alrakis → Ross 154** (relaxed, sparse passes,
   destination swelling ahead — the "normal" feel for contrast).
3. **The dead end — Grumium → Haven** (blocked; fly into Mimosa at 891 GU, clip
   ends on its flare — the drop-out made visible).

Each has Replay; captions pull real distance/ticks/binding-star/gap.

## Extensibility (3 → 2 → 1)

Every clip is just `playWarp(canvas, {origin, dest, stars})`, so later forms are
pure wiring:
- **Standalone page (2):** two `<select>`s (origin/destination) + Play; optional
  raw-heading mode (fly a bearing into the void).
- **Jump-page embed (1):** a "Fly this route" button per Direct/Station row →
  `playWarp` with that destination. Zero engine changes.

## Build integration & testing

- **Go:** add `writeStarsJSON(path, systems)` to `cmd/generate-items-kb`, called
  from `writeSystemPages` next to `writeRoutesJSON`. Emits `stars.json` for all
  systems, `class` from the sun POI (blank if absent), deterministic order.
  TDD-covered: all systems present, class populated/blank correctly, valid JSON
  round-trip.
- **Static assets:** `kb/warp.js` and `kb/did_you_know/hyperspace_warp.html`
  hand-authored; a Did You Know card links the demo.
- **Testing scope:** Go side is unit-tested. The JS engine has no auto-tests
  (no JS harness in this repo, per project norms); risky math is factored into
  small pure functions and verified manually in a browser.
- `go build ./...`, `go test ./...`, `golangci-lint` stay clean; regenerate and
  confirm only `stars.json` is added (plus the new static files). Check
  `.gitignore` doesn't swallow `kb/warp.js` / the new HTML before committing.
