# Empire Economy Analysis — Design

**Date:** 2026-05-26
**Status:** Approved, building.

## Goal

Produce a report that answers, using game data + KB cross-references:

1. Which intermediate components (steel_plate, circuit_board, etc.) carry the most weight across all recipes?
2. For each item and ship, how many of the 5 empires can build it end-to-end using only base materials sourced from their own systems? (0 / 1 / 2 / 3 / 4 / 5)
3. Per-empire scarcity: weighted by POI richness, how comfortably can each empire source the inputs it needs?

## Scope (first pass)

- **Products:** items + ships (505 + 288). Facilities deferred until the report shape stabilizes.
- **Base inputs:** all `bom` package "base" materials — ores + materials + gases. Anything the BoM calculator treats as a terminal leaf.
- **Empires:** the five named empires from `systems.empire` (`nebula`, `outerrim`, `crimson`, `solarian`, `voidborn`). Unaligned systems (`empire = ''`) are reported separately but not counted toward any empire's self-sufficiency.

## Output & delivery

- **Phase 1 (now):** CLI binary at `cmd/analyze-empire-economy/` that writes a single Markdown file to `docs/analysis/empire-economy.md` and prints a short summary to stdout.
- **Phase 2 (later, after the shape proves out):** graduate the queries into a new KB section (`kb/analysis/` or similar) regenerated by `generate-items-kb`.

No DB writes. Read-only over `crafting.db`, `spacemolt-knowledge.db`, and `catalog_ships.json`.

## Pipeline

1. Load items, recipes, ships → build BoM map via `pkg/bom`.
2. Load empire ↔ resource presence map and per-resource richness totals.
3. Compute galaxy-wide richness totals (denominator for market share).
4. Per product: which empires have *all* its base materials (presence) + per-empire ease (richness-based).
5. Compute component popularity (direct + transitive) across all recipes.
6. Render Markdown.


## Key definitions

### Component popularity
- "Intermediate" = any item that is both a recipe output and a recipe input. Excludes raw base materials and pure end-products.
- **Direct demand** = number of distinct recipes whose `recipe_inputs` references the item.
- **Transitive demand** = number of distinct final products (items + ships) whose BoM tree contains the item at any depth.
- Reported as two ranked tables side-by-side, plus a "Worth Stockpiling" callout for items in the top 10 of both.

### Empire self-sufficiency (presence-based)
- For a product P, let `base(P)` be P's BoM base materials.
- Empire E *can solo-build* P iff every material in `base(P)` is present in at least one POI within E's systems.
- "Exclusive" product for E = only E can solo-build it.
- Cross-empire dependency matrix: `M[A][B]` = number of products A *cannot* solo-build that A∪B *can* solo-build (i.e., trading with B unlocks N products for A).

### Per-empire richness (continuous)
- For each base resource R: `share[E][R] = sum(richness in E's POIs) / sum(richness across all POIs)`.
- Verdict bands: ≥40% Dominant, 15–40% Sufficient, 1–15% Scarce, 0 Missing.
- **Ease score** for empire E building product P = `min over R in base(P) of share[E][R]` (bottleneck — the weakest input gates comfort).

### Composite Self-Sufficiency Index (0–100)
```
SSI[E] = 0.5 * (fraction of all products E can solo-build) * 100
       + 0.5 * (mean ease across E's solo-buildable products) * 100
```
Breadth + comfort, equal weight. Re-weight later if one half dominates the story.

## Run model

```
go run ./cmd/analyze-empire-economy
```

Defaults to the same DB paths `generate-items-kb` uses (`../../spacemolt-crafting-server/database/crafting.db`, `../spacemolt-knowledge.db`, catalog dir under `../spacemolt/data/game-api`). Writes `docs/analysis/empire-economy.md`. No flags in v1.

## Non-goals (deferred)

- Facilities (defer until items+ships report shape is dialled in).
- Tunable thresholds via flags (hard-coded for v1).
- HTML/KB integration (phase 2).
- Trade-route or fuel-cost weighting (just empire-internal presence/richness).
- Recipe `crafting_time` or labor cost — out of scope here.

## Future extensions

- Add facilities to product universe.
- Promote stable queries to a `kb/analysis/` HTML section.
- Per-system (not per-empire) self-sufficiency — useful for "which capital systems are most defensible economically?"
- Time-series: re-run periodically and chart how empire SSI shifts as the galaxy is explored.
